# Omuse 0.11.0 — A clearer canvas

**11 October 2026 · Linux / Omarchy source pre-release · unsigned experimental Windows**

Keep useful actions close to your artwork, arrange editable content with
retained layout rules, and give AI proposals room to be compared. Omuse 0.11
brings these workflows into the existing canvas, layers and Undo history.

## Reach the right action

Select **Move — V** and a layer to see a compact action bar at the bottom of
the canvas. Photos offer Develop, Cut out and Add mask; text offers Edit text;
artwork offers Edit artwork. Pixel selections, multiple layers, vector drafts
and floating pixels each expose their relevant actions.

The bar follows your selection and customised shortcuts, wraps within narrow
canvases, and stays put when you zoom. It hides during painting, dragging,
text entry and modal work. Actions keep their usual lock and selection
requirements. Choose **×** to hide the bar and **Ctrl+K → Canvas actions** to
bring it back.

Keyboard focus returns to the canvas before an action opens its own editor or
dialog. Ungroup and Hide no longer leave focus on a control that has disappeared,
so ordinary Undo remains available immediately afterward.

## Arrange content that stays editable

Select adjacent photo, live text or vector layers from the same folder, then
choose **Auto layout** from the canvas bar or **Ctrl+K**.

- Set horizontal or vertical flow, gap, padding and alignment.
- Let a frame hug its content or give it fixed dimensions. Members can hug
  their source, use a fixed size or share available space with Fill.
- Wrap members within a fixed main-axis dimension. Wrap supports Hug and Fixed
  members; Fill and Wrap cannot be combined.
- Keep rules in the `.omuse` project. Supported text, visibility and layer-order
  edits reflow the frame as part of the same Undo step.
- Reopen Auto layout to adjust the rules, or choose **Release rules** to keep
  the arrangement and resume ordinary positioning. Ungroup also releases the
  relationship.

Sources remain editable. Move the whole frame with the Move tool; change its
dimensions in Auto layout. Layout uses source rectangles, including transparent
padding, and Fill scales text instead of rewrapping it. Fixed frames do not
clip overflowing children.

Floating-pixel edits now preserve selection placement when a managed source
grows and reflows. Frame selection bounds also follow their retained fractional
extent instead of the document dimensions.

Follow the [illustrated canvas workflow](https://github.com/Sugata-Software/Omuse/blob/main/docs/user-guide/canvas-workflows.md)
for controls, sizing rules and editing limits.

## Compare AI proposals before keeping them

Completed AI tasks now show **Before / After** together. Enlarge either preview
or choose **Changes** to highlight visible differences. Pin a retained variation
to compare it with another, then choose **Compare with original** to return to
the source. The document changes only when you Keep a result.

Rectangular previews now keep their proportions. The completed-review composer
collapses to a compact footer so the artwork has more room. **Refine result**
and **Open composer** return to the same prompt and references;
**Collapse composer · keep draft** preserves them for later. Active requests
retain progress and Stop, and a collapsed draft cannot submit through Ctrl+Enter.

Comparing saved previews makes no provider request. Generation and refinement
retain the existing connection, consent and provider requirements. The Changes
percentage describes a reduced preview with a visibility threshold, not a
full-resolution audit or a judgement of image quality. Comparisons require
compatible canvas and page framing; a result without its original preview never
substitutes the current canvas as a false Before image.

## Project compatibility and practical limits

**Save As a separate `.omuse` project before adding retained layout.** Projects
with layout rules use native format 15; Omuse 0.10.0 and older refuse them.
Releasing rules in the newer app removes that layout requirement, while other
features keep their own format requirements. Keep the retained master and save
a separate released copy for older editing. Rolling back the application does
not downgrade artwork. Ordinary exported images remain compatible as before.

Frames accept direct, unrotated photo, live text and vector layers. Nested
frames/folders, adjustment layers and clipping relationships are outside this
release. Layout supports up to 64 frames, 256 children per frame and 2,048 total
members; these are admission limits, not measured performance guarantees.
Independent member positioning, rotation and multi-member transforms require
releasing the applicable rules. Destructive Image Size resampling also requires
Release rules first; DPI-only changes remain supported.

Windows remains unsigned experimental. Interactive Windows, broader hardware,
foreground Wayland interaction beyond scripted checks, resource-limit performance
and live AI providers are qualified separately. This update does not establish
new subscription access or photographic-quality guarantees.

## Install and release evidence

On **Arch/Omarchy x86_64**, build and install the tested source revision with:

```sh
curl -fsSL https://raw.githubusercontent.com/Sugata-Software/Omuse/main/install.sh | bash
```

The installer handles dependencies and builds the tested application locally;
allow time for the first build. Already-built application bundles and checksums
are distributed through the
[0.11.0 release page](https://github.com/Sugata-Software/Omuse/releases/tag/v0.11.0)
when attached. Follow the
[bundle installation guide](https://github.com/Sugata-Software/Omuse/blob/main/docs/downloadable-releases.md)
for those archives; GitHub automatic source archives are source code only.
For Windows, extract the complete ZIP and retain `lib`, `models` and `licenses`
beside `omuse.exe`. Keep the previous complete installation for rollback.

[`e72bccdcef066cb6ab60a99faa9d7609de86c2e4`](https://github.com/Sugata-Software/Omuse/commit/e72bccdcef066cb6ab60a99faa9d7609de86c2e4).
