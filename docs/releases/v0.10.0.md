# Omuse 0.10.0 — Shape your next idea

**11 October 2026 · Linux / Omarchy source pre-release · unsigned experimental Windows**

Shape artwork directly on your photo canvas. Omuse 0.10 brings region-based
Shape Builder, better curve editing, editable repeats and more precise
snapping, alongside Photoshop exchange and responsive photo workflows.

## Build shapes on the canvas

- **Drag to build.** Select 2–8 consecutive opaque filled paths and press
  **Alt+M** for Shape Builder. Drag through regions to merge; hold Alt when
  starting to erase them. Holes remain empty. Review the editable result,
  compare with Undo, then keep the artwork as one document edit.
- **Keep curves useful.** Unite, Subtract, Intersect, Exclude and Divide use
  Bézier geometry. Simplify reduces points within its fitting tolerance;
  Offset expands or insets a contour; Outline strokes creates filled geometry.
  Split at a node or join endpoints within one object.
- **Place points precisely.** Node and handle drags snap within six screen
  pixels to other anchors, visible guides or the grid. Hold Shift to bypass
  snapping while keeping the existing angle constraint.
- **Repeat a motif.** Preview a grid or radial arrangement, choose orientation,
  then keep independent editable copies. Originals remain intact. These are
  ordinary saved objects, not a persistent live repeat effect.
- **Bring in more SVG artwork.** Supported text becomes glyph outlines;
  supported gradient and transformed strokes become filled outlines. Conversion
  warnings explain font substitution and changes to editability.

Follow the [illustrated vector workflow](https://github.com/Sugata-Software/Omuse/blob/main/docs/user-guide/photo-vector-development.md)
for controls, prerequisites and Undo behavior.

## Finish photos and exchange a copy

- **Retouch without blocking the stroke calculation.** Blur, Smudge and Liquify
  compute in a background job on release. Escape or Cancel requests cancellation
  before commit; a completed stroke remains one Undo step. Original source
  dimensions, selections and mask placement remain protected.
- **See tone changes sooner.** Eligible ordinary photos show a quick sampled
  Camera Raw preview, then automatically refine to full detail. Scopes and
  colour sampling wait for the full result; Apply grades original full-size
  pixels. New tone mapping avoids the recorded near-black colour spikes and
  neutral-gradient reversals while preserving legacy recipes.
- **Compare local removal methods.** Controlled removal adds **Texture ·
  experimental**, with **Context** still the default. Choose clean nearby
  donors and inspect the result before keeping its editable recipe. Photo
  checks found useful repairs and visible seams; Texture is not always better.
- **Export a layered PSD.** Supported layers become 8-bit sRGB pixel layers.
  **Ctrl+K → Export conversion report** lists rendered content and the
  destination filename. Live text, vectors, effects and retained precision
  stay in the `.omuse` master, not in the converted PSD.
- **Open a 16-bit Photoshop composite.** Supported RGB PSD/PSB merged previews
  retain interpreted 16-bit samples and supported ICC conversion in one source
  layer. This does not rebuild the original Photoshop layer stack.

Merged PSD transparency now follows the white-matte convention expected by
independent readers. Layer RGBA remains unchanged; merged-preview rounding
is expected. Read the [exchange guide](https://github.com/Sugata-Software/Omuse/blob/main/docs/psd-exchange.md)
for supported compositing, size limits and a safe flattened-copy workflow.

## Refine a content collection

Design & layout can identify existing text on another collection page from
bounded page context. Ask for a targeted revision, review it, then Keep once;
Undo restores the previous artwork. Inactive page images are not added to this
context. Native vector finishing commands can also be proposed against known
object IDs and reviewed before committing. These command changes do not
establish new live-provider availability or model accuracy.

## Compatibility and practical limits

Keep an editable `.omuse` original before updating or exchanging artwork.
New Texture removal and SmoothV1 tone recipes require a reader that understands
their versions; an older editor can refuse the containing project. Rasterize
those results in a separate copy using the newer build before backward editing.
Existing unversioned tone recipes keep Legacy behavior. Ordinary Camera Raw
Apply produces raster pixels. Rolling back an app does not downgrade projects.

Native retouch and Camera Raw remain bounded 8-bit workflows up to 16 MP.
Quick previews apply only to eligible simple compositions and pointwise colour
changes; they do not add GPU grading or unify sensor-RAW development. Texture
accepts sources up to 16,777,216 pixels, with a four-million-pixel search region
and at most 250,000 selected pixels; its work budget can refuse smaller inputs.
Context retains its four-million-pixel source limit.

Shape Builder requires opaque fills without strokes. Geometry operations and
repeat generation have work/output caps. SVG clipping, general isolated group
compositing, patterns, live repeats, variable-width strokes and mesh tools
remain outside this release. PSD interchange is a documented subset, not
lossless Photoshop round-trip. Windows remains unsigned experimental, with
interactive Windows, live-provider and clean-machine checks qualified separately.

## Install and release evidence

On **Arch/Omarchy x86_64**, install the tested source revision:

```sh
curl -fsSL https://raw.githubusercontent.com/Sugata-Software/Omuse/main/install.sh | bash
```

Download application archives and checksums from this
[release page](https://github.com/Sugata-Software/Omuse/releases/tag/v0.10.0)
when attached. GitHub automatic source archives are not installed apps.
For Windows, extract the complete ZIP and keep `lib`, `models` and `licenses`
beside `omuse.exe`; keep the previous folder for rollback. Linux retains its
previous complete installation for `omuse-manage rollback`.
