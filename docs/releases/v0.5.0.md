# Omuse 0.5.0 — One project, one extension

**30 September 2026 · Arch Linux / Omarchy · Linux x86_64 source pre-release**

Every new editable project now uses **`.omuse`**: a photo with layers, a design,
or a multi-page Create collection. Save dialogs add the extension automatically.
Recovery snapshots, nested pages/components, CLI examples and the manual use
the same convention.

## Your existing work stays usable

Open an older `.comp` project normally. Its first **Ctrl+S** offers an `.omuse`
copy and keeps the original project. If that name already exists, choose another
name or explicitly **Replace project**. Omuse checks the destination again before
publishing a save, protecting edits made by another window or process.

Both project types are directory packages. Copy the complete directory when
moving or backing up artwork. Their manifests identify the contents; the shared
extension does not flatten layers or collection pages.

Create collections now save schema **version 2**, with nested `.omuse` pages and
components. Existing **version 1** collections still open, including inactive
pages, resources, brand data and reusable components. Saving upgrades them to
version 2. **Omuse 0.4.0 and earlier cannot read version 2 collections**: use
**Save As** to a separate location to retain a version 1 copy for those releases.
Reading a project alone never upgrades it.

## Batch and Linux fixes

Batch recipes now accept `.omuse` canvases and collections alongside images and
legacy `.comp` projects. A collection uses its saved active page; use Create's
content-pack export for multiple pages. Output collisions remain protected.
Projects opened with a trailing slash from shell completion save correctly.

## Install or update

```sh
curl -fsSL https://raw.githubusercontent.com/Sugata-Software/Omuse/main/install.sh | bash
```

The first installation compiles from source. Save your work and reopen Omuse
after updating; existing windows continue running their original version.
The installer retains the previous complete app for rollback, but rollback does
not convert version 2 collections back to version 1. Keep a separate project copy
if you need to return to an older release.
